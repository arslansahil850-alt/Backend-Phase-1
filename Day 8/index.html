THE LESSONS

01

What is HTTP?

HTTP stands for Hypertext Transfer Protocol. It defines how clients and servers exchange requests and responses. 

Browser
   |
   | HTTP Request
   v
Web Server
   |
   | HTTP Response
   v
Browser
HTTP defines the communication rules.
02

HTTP Requests

A request is a message sent by a client to a server. It can contain a method, URL, headers, and an optional body. 

GET /products HTTP/1.1
Host: example.com
Accept: application/json
GET requests commonly retrieve data.
03

HTTP Responses

A response contains a status code, headers, and sometimes a body containing HTML, JSON, or other data. 

HTTP/1.1 200 OK
Content-Type: application/json

{"message":"Success"}
200 means the request succeeded.
04

HTTP Methods

Methods describe the intended action. GET retrieves data, POST submits data, PUT replaces a resource, PATCH updates part of a resource, and DELETE requests removal. 

GET     /users
POST    /users
PUT     /users/5
PATCH   /users/5
DELETE  /users/5
The method helps describe the operation.
05

Status Codes

Status codes tell the client the outcome of its request. Their first digit indicates the general category. 

200 OK
201 Created
301 Moved Permanently
400 Bad Request
401 Unauthorized
403 Forbidden
404 Not Found
500 Internal Server Error
404 means the requested resource was not found.
06

HTTP Headers

Headers provide additional information about requests and responses, such as content type, accepted formats, and authorization details. 

Content-Type: application/json
Accept: application/json
Authorization: Bearer TOKEN
Headers describe the message and its context.
REQUEST TO RESPONSE

How HTTP works

1

Client sends

The browser or application sends an HTTP request.

→
2

Server processes

→
3

Server responds

The server returns a status code, headers, and possibly a body.

HTTP vs HTTPS

HTTPS uses HTTP over a connection secured with TLS. This protects data in transit and helps authenticate the server. For real websites, HTTPS is the standard choice.

Remember this

HTTP is a stateless protocol: each request is treated independently by default. Applications can use cookies, sessions, or tokens to maintain user state across requests.
